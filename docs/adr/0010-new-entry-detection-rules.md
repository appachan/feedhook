# 10. New entry detection rules

Date: 2026-09-27

## Status

Accepted

## Context

どの記事を「新着」として投稿するかを決める。初回の実行で過去の記事を全部流したり、フィード側の不具合(ID の振り直し、過去記事の再配信)で大量に投稿したりするのは避けたい。

feed-rs は、ID(RSS の `guid`、Atom の `id`)のない記事に対して、次の順で ID を生成する。

1. 最初のリンクとタイトルのハッシュ
2. リンクがなければ、フィードの URL とタイトルのハッシュ
3. どちらもなければ、ランダムな UUID

## Decision

- 記事の ID は feed-rs が返す `id` を使う。ID のない記事は、feed-rs が生成するハッシュの ID を使う(解析のときにフィードの URL を渡す)
- リンクもタイトルもない記事は、ID が起動のたびに変わってしまうため、ID を空にして処理の対象から外す
- 状態にまだないフィード(初回)は、今ある記事をすべて既読にして、何も投稿しない
- それ以外は、既読でない ID を持ち、かつ公開日(なければ更新日)が `max_age_hours`(既定は 24 時間)以内の記事を、古い順に投稿する
- 公開日も更新日もない記事は投稿しない
- すでに投稿した記事の本文が更新されても(インシデントの続報など)、ID が同じなので再投稿しない

## Consequences

- 初回の実行やフィードの追加で、過去の記事が流れない
- フィード側の不具合による再配信は、公開日が古ければ投稿されない
- ID のない記事は、タイトルを修正されると別の記事として扱われ、公開日が新しければもう一度投稿される
- 日付を持たないフィードは投稿されない。そういうフィードを扱いたくなったら、条件を見直す
- 続報を通知したくなったら、更新日時や本文の変化で再投稿する機能を追加する
